## 第一阶段 - 基础设施搭建

### 第 1 期：项目总览

- 项目介绍
- 项目收获
- 业务流程
- 功能模块
- 技术选型
- 架构设计
- 准备工作
- 学习大纲

### 第 2 期：项目搭建和用户认证

- monorepo 结构设计：`backend/` + `frontend/`，根目录 `docker-compose.yml` 统一管理
- Docker Compose 编排 PostgreSQL、Redis、MinIO 三个中间件容器
- FastAPI 后端入口、健康检查接口、Alembic 数据库迁移
- Vite + React 19 前端初始化，配置反向代理到后端
- Tailwind CSS design token 统一视觉风格
- 账号密码注册登录，密码用 bcrypt 哈希存储
- JWT 存入 httpOnly Cookie，对比 localStorage 方案讲清优劣
- 落地页、登录注册页、全局路由守卫

### 第 3 期：对象存储和 AI 文生图

- 什么是对象存储，为什么需要自己存图而不是用模型返回的临时链接
- MinIO 封装：上传校验、签名 URL、Asset 数据模型
- 什么是 Provider 抽象层，如何隔离具体模型实现
- MockImageProvider：Pillow 合成占位图，零成本本地开发
- DashScopeProvider：接入百炼原生 API，创建任务 → 轮询结果
- ARQ 异步队列：生图任务提交到 Redis，Worker 独立进程消费
- SSE 实时进度推送，浏览器自动重连
- 创作页和四宫格候选选图页

## 第二阶段 - 编辑器和 Agent

### 第 4 期：编辑器画布和会话管理

- EditSession 模型设计：关联用户、源图、当前版本号
- revisionId 版本链：每次编辑产生新版本，版本链式追踪
- react-konva 画布搭建：图层渲染、视口缩放平移
- Zustand 管理画布视口状态
- 撤销重做：基于 revision 链，前端一键回退或前进
- 会话图片墙：展示所有历史版本和候选图，点选采用
- 前后对比滑杆

### 第 5 期：Agent 对话框架

- 什么是 ToolRegistry，为什么不直接 if-else 分发工具调用
- 工具基类设计：名称、描述、参数 schema、执行函数统一注册
- 什么是 LangGraph，和普通函数调用链的区别
- LangChain 怎么接入规划模型：ChatOpenAI、bind_tools、工具签名转换
- 搭建最小图：`plan → verify → END`，自然语言驱动工具调用
- 单步直接执行：只有一个工具时跳过确认，直接执行
- 前端对话组件：消息列表、输入框、计划卡片

### 第 6 期：编辑工具

- 抠图 `remove_background`：rembg 本地模型，纯 CPU 运行
- 调色 `adjust_image`：亮度、对比度、饱和度、色温参数化调节
- 画布变换工具集：裁剪、翻转、缩放、旋转、移动
- 图层控制：透明度、显隐切换、层序调整
- 换背景、扩图、超分：百炼生成式 API + ARQ 异步执行
- 候选采用机制：生成结果进入图片墙，用户选择后替换当前图
- 前端工具栏和生成式编辑面板

### 第 7 期：区域选择和局部编辑

- 什么是 SAM（Segment Anything Model），为什么选 vit_b 量化版
- 点选交互：首次点击计算 embedding，后续点击只跑 decoder（毫秒级）
- 笔刷遮罩：自由绘制选区，生成 mask 发送后端
- 选区绑定 revisionId，切换版本时自动恢复选区状态
- 选区 Redis 临时存储，高频交互不落数据库
- 局部消除：inpainting 移除选区内容，AI 自动填补
- 局部替换：用提示词描述替换选区内容

## 第三阶段 - 高级能力和部署

### 第 8 期：图层拆分和图层操作

- 什么是语义拆层，为什么不做全自动全图拆层
- 自动拆分为主体层和背景层，可选 OCR 文字层
- 点选任意物体按需提升为独立图层，背景自动修复
- 幂等校验：执行前检查是否已经是独立图层
- 图层面板：显隐切换、透明度调节、拖拽排序
- 图层独立操作：每个图层可单独缩放、调色、移动
- LayerDocument 持久化：JSONB 存储，切图片再切回来图层不丢失

### 第 9 期：多步计划和人机协作

- LLM 输出结构化 JSON 计划（最多 8 步）
- 服务端校验：工具存在性、参数合法性、依赖补全、环检测
- 按依赖拓扑排序，就绪步骤自动执行
- 什么是 HITL（Human-in-the-Loop），为什么需要人工确认
- 计划卡片：确认执行、单步重试、取消后续
- 单步 vs 多步：单步直接执行不经确认，多步必须确认

### 第 10 期：部署上线

- Dockerfile 多阶段构建：前端 build → Python 镜像托管 API + 静态资源
- docker-compose profile 设计：默认只起中间件，`--profile deploy` 起完整服务
- 本地 CV 模型卷挂载，app 和 worker 共享，避免重复下载
- 部署到云服务器：购买服务器、传代码、配置生产环境、三条命令启动
- 域名和反向代理（可选）：Nginx 反代、SSE 不缓冲、HTTPS 证书
- 环境变量切换 Mock 到真实模型，冒烟测试全链路验证

## 扩展篇：项目扩展思路（官方 7 个扩展点）

1. **智能改尺寸、营销图模板、批量处理、ZIP 导出** —— ✅ 本仓库已完成（fork 时已实现）
2. **Agent 规划过程逐 token 流式输出**，降低等待感 —— 🔲 未做
3. **LangGraph checkpoint 持久化**：刷新页面后恢复 Agent 执行进度 —— 🔲 未做
4. **接入更多模型平台**，验证 Provider 抽象层扩展性 —— 🟡 部分完成（本次已新增 `openai` 兼容 Provider，见 `../CHANGES.md`）
5. **多用户并发控制**：信号量限制同时生成请求数量 —— 🔲 未做
6. **安全加固**：限流、敏感词过滤、上传内容审核 —— 🔲 未做（优化路线 Track A 有重叠项）
7. **商业化方向**：会员付费、API 开放、企业定制 —— 🔲 未做

> 其中第 2、3、5、6 项的技术底座与《代码优化方案》Track A（稳定性安全）/ Track B（Agent 增强）重叠：
> 做完流式输出（B 线）、checkpoint 持久化（B 线）、信号量限流（A 线）、安全加固（A 线），
> 等于同时拿下 4 个官方扩展点。完整方案见工作区 `ai-picture-editor-代码优化方案.html` 与 `../OPTIMIZATION-ROADMAP.md`。
